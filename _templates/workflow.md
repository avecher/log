
# Порядок работы с лабораторией «Здесь был Буратино»

### 1. Вход в редактор
1. Открой репозиторий `avecher/weblog` на GitHub.
2. В адресной строке замени `github.com` на `github.dev`.
3. Нажми Enter. Загрузится VS Code в браузере (адрес может смениться на `vscode.dev/github/...` — это норма).

### 2. Создание новой записи
1. Слева в панели файлов найди папку `_posts`.
2. Наведи курсор на папку → нажми иконку «New File».
3. Имя файла строго по формату: `ГГГГ-ММ-ДД-название.md` (например, `2026-11-15-derevyannost.md`).
4. Вставь шаблон фронтматера (скопируй из `_templates/memo.md` или используй сниппет `memo` + Tab, если настроен):
   ```markdown
   ---
   layout: default
   title: Заголовок записи
   date: ГГГГ-ММ-ДД
   ---
   
   Текст записи начинается с новой строки после пустой строки.
   ```
5. Пиши текст. Для предпросмотра нажми `Ctrl+Shift+V`.

### 3. Фиксация изменений
1. Перейди во вкладку Source Control (иконка веточки слева).
2. Увидишь список измененных файлов. Наведи на файл → нажми «+», чтобы добавить его к коммиту.
3. В поле «Message» напиши короткое описание изменений (например, «Добавлена заметка о деревянности»).
4. Нажми **Commit & Push**.

### 4. Проверка результата
1. Подожди 2–3 минуты (Jekyll собирает сайт на стороне GitHub).
2. Открой `https://avecher.github.io/weblog/`.
3. Убедись, что запись появилась в ленте и отображается корректно.

### ⛔ Чего НЕ делать
-   Не использовать Codespaces (это избыточно для статики).
-   Не ставить GitHub Desktop (дублирует функции VS Code).
-   Не включать Copilot при написании текстов хроники (сохраняй «деревянность»).
-   Не загружать медиа >100 МБ прямо в `_posts` (используй Releases или внешние ссылки).
-   Не писать HTML-файлы с Markdown-разметкой внутри (Jekyll не конвертирует `.html`).
